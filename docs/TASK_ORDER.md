# TRNT 작업 순서 (Phase 1)

> 의존성을 반영한 **지금부터 할 일** 체크리스트.  
> 위에서부터 순서대로 진행하면 됩니다.

---

## 1단계: 기반 잡기 (1주)

| 순서 | 작업 | 이유 |
|------|------|------|
| **1** | **저장소 구조 확정** | `frontend/`, `backend/` 폴더 생성, 루트 README에 구조 설명 추가 |
| **2** | **PostgreSQL 스키마 초안** | ERD 작성, `users` / `branches` / `scenarios` 테이블 정의. 이후 API가 이걸 기준으로 구현됨 |
| **3** | **FastAPI 프로젝트 초기화** | `backend/` 안에 FastAPI 앱, Dockerfile, `GET /health` 헬스체크. DB 연결 설정(나중에 연결) |
| **4** | **Next.js 프로젝트 초기화** | `frontend/` 안에 Next.js 앱, TypeScript·ESLint 설정. Vercel 연동(또는 배포 설정만 준비) |

**완료 기준:** 로컬에서 `backend` 헬스체크 응답, `frontend` `npm run dev`로 화면 출력

---

## 2단계: 백엔드 핵심 API (2주)

| 순서 | 작업 | 이유 |
|------|------|------|
| **5** | **DB 마이그레이션 및 연결** | 1단계 스키마로 테이블 생성, FastAPI에서 PostgreSQL 연결 |
| **6** | **사용자·세션 API** | 회원가입/로그인 또는 **익명 세션**만 구현. MVP는 익명 세션만 해도 됨 |
| **7** | **분기점(Branch) CRUD API** | `POST/GET/PATCH/DELETE /api/v1/branches`. 프론트에서 입력한 분기점 저장 |
| **8** | **프롬프트 템플릿 설계** | 톤/장르/상세도별 “선택 → 시나리오” 프롬프트 1세트. AI 연동 전에 문서로 고정 |
| **9** | **시나리오 생성 API (AI 연동)** | `POST /api/v1/scenarios/generate`. Groq 또는 OpenRouter 호출, 프롬프트 주입, 텍스트 반환 |
| **10** | **시나리오 저장·조회 API** | 생성 결과를 DB에 저장, `GET /api/v1/scenarios`, `GET /api/v1/scenarios/{id}` |
| **11** | **Rate limit·에러 처리** | 일 3회 무료 등 제한, 4xx/5xx 일관 처리, 로깅 |

**완료 기준:** Postman/curl로 분기점 생성 → 시나리오 생성 → 저장 → 조회 한 번에 성공

---

## 3단계: 프론트엔드 UI (2주)

| 순서 | 작업 | 이유 |
|------|------|------|
| **12** | **디자인 시스템 기초** | 색상, 폰트, 버튼/카드 컴포넌트. Figma 없이도 `globals.css` + 컴포넌트로 시작 가능 |
| **13** | **랜딩·온보딩 페이지** | `/`, `/onboarding`. 서비스 소개 + “첫 분기점 입력하기” CTA |
| **14** | **분기점 입력 폼** | `/branch/new`. 시간, 원래 선택, 대안 선택, 맥락, 현재 상태 → Branch API 호출 |
| **15** | **톤/장르/상세도 선택 UI** | 분기점 저장 후 다음 스텝. 선택값을 시나리오 생성 API에 전달 |
| **16** | **시나리오 생성·결과 화면** | 로딩 표시 → `POST /scenarios/generate` → 결과 텍스트 표시, 저장 버튼 |
| **17** | **시나리오 목록·상세** | `/scenarios`, `/scenario/[id]`. 저장된 시나리오 목록 및 상세 읽기 |
| **18** | **반응형·접근성 점검** | 모바일 뷰, 포커스/키보드 기본 확인 |

**완료 기준:** 브라우저에서 분기점 입력 → 시나리오 생성 → 저장 → 목록에서 확인까지 한 번에 성공

---

## 4단계: 인프라·배포 (1주)

| 순서 | 작업 | 이유 |
|------|------|------|
| **19** | **Docker Compose (API + DB)** | NAS 또는 로컬에서 `docker-compose up`으로 API + PostgreSQL 기동, 내부 통신 확인 |
| **20** | **Cloudflare Tunnel (선택)** | NAS 24시간 운영 시 외부 HTTPS 노출. 로컬만 쓰면 나중에 해도 됨 |
| **21** | **Vercel에 프론트 배포** | `frontend` 배포, 환경변수에 API URL 설정 |
| **22** | **E2E 1회 + 피드백 폼** | “분기점 입력 → 시나리오 생성 → 저장” 시나리오 1개 문서화. 베타용 피드백 폼 링크 준비 |

**완료 기준:** 배포 URL에서 전체 플로우 동작, 피드백 링크 공개

## 한 줄 요약 순서

```
1. 저장소 구조 → 2. DB 스키마 → 3. FastAPI 초기화 → 4. Next.js 초기화
→ 5. DB 연결 → 6. 사용자/세션 → 7. Branch CRUD → 8. 프롬프트 설계 → 9. 시나리오 생성 API → 10. 시나리오 저장/조회 → 11. Rate limit
→ 12. 디자인 기초 → 13. 랜딩 → 14. 분기점 폼 → 15. 톤/장르 UI → 16. 시나리오 결과 → 17. 시나리오 목록 → 18. 반응형
→ 19. Docker → 20. Cloudflare(선택) → 21. Vercel 배포 → 22. E2E·피드백
→ 23. 베타 피드백 수집 → 24. 회고
```
